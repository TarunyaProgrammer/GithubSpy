# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People new to open source who are considering contributing to a GitHub project. They need a clear view of how active the project is and how much contributor activity they may encounter before deciding where to spend their time.

## Product Purpose

GitHub Spy turns public pull-request activity into an approachable overview that helps a prospective contributor assess a repository before they get involved. Success means a visitor can understand a project's activity, responsiveness, and contributor landscape without needing to know GitHub analytics jargon.

## Positioning

Rather than presenting repository activity as a technical dashboard, GitHub Spy frames it around the practical question a new contributor has: “Is this a project where I can realistically contribute?”

## Operating Context

Visitors paste a public GitHub repository link, choose a recent time period, and review pull-request outcomes, review timing, people who contribute, and recent pull requests. They may open a contributor profile for more detail or open an individual pull request on GitHub.

## Capabilities and Constraints

- Uses public GitHub repository and pull-request data.
- A personal GitHub token can increase the number of API requests available per hour.
- The existing React, Vite, Tailwind, and GitHub API integration remain in use.
- Interface language should be understandable to a beginner while retaining familiar GitHub terms where needed.

## Brand Commitments

The product name is GitHub Spy. The user has authorized broad changes to the interface when they make the experience more intuitive for prospective contributors.

## Evidence on Hand

The app already displays repository metrics, pull-request outcomes, review timing, contributor lists, individual contributor details, and recent pull requests. No external customer claims, testimonials, or performance benchmarks are available.

## Product Principles

- Start with the contributor’s decision, not the data source.
- Explain every metric in plain language and pair it with why it matters.
- Make the next useful action obvious at every state.
- Keep advanced detail available without making it a prerequisite for understanding.
- Treat rate limits and data gaps as recoverable situations, not technical failures.

## Accessibility & Inclusion

Use clear language, visible keyboard focus, descriptive labels, and layouts that remain understandable on small screens and at high zoom.
